# Технические и функциональные требования к выполнению Контрольной работы № 2 (JavaFX)

## 1. Общие требования и преемственность
1. **Преемственность с КР № 1:**
   * Сохраняются: предметная область, вариант, бизнес-правила, состав команды (4 человека).
   * Используется база данных PostgreSQL, спроектированная и созданная в рамках КР № 1.
2. **Роль демонстрационного архива и Docker:**
   * Перед началом разработки необходимо полностью развернуть и запустить проект из архива через Docker Compose (`backend/docker-compose.yml` или `start-compose.ps1`), проверив работу веб-системы (`http://localhost:8080/`) и healthcheck.
   * Исходный `javafx-client` из архива служит **только примером** организации UI, FXML и архитектуры.
3. **Ключевое отличие собственной КР № 2:**
   * В отличие от демонстрационного JavaFX-клиента (который общается с backend через REST API), **собственное приложение команды должно подключаться напрямую к PostgreSQL через JDBC**.

---

## 2. Стек технологий и окружение
* **Язык и платформа:** Java 21.
* **UI-фреймворк:** JavaFX 21 (`javafx-controls`, `javafx-fxml`, плагин `javafx-maven-plugin`).
* **Сборщик проекта:** Apache Maven (версия 3.9+).
* **СУБД и драйвер:** PostgreSQL + PostgreSQL JDBC Driver (рекомендуется `42.7.x`).
* **Контейнеризация:** Docker / Docker Desktop (с поддержкой `docker compose`).
* **Вспомогательные библиотеки:** SLF4J (для логирования), Apache POI (в случае экспорта в `.xlsx`).

---

## 3. Архитектурные требования
Приложение должно быть строго разделено на слои (**многослойная архитектура**):
1. **View (Представление):** файлы разметки `.fxml` и таблицы стилей `.css`.
2. **Controller (Контроллеры):** классы JavaFX, обрабатывающие пользовательские действия и управляющие элементами UI.
3. **Service (Бизнес-логика):** валидация, расчет статистики, обработка бизнес-правил предметной области.
4. **Repository / DAO (Доступ к данным):** выполнение SQL-запросов через JDBC, маппинг `ResultSet` в доменные модели.
5. **Database (БД):** PostgreSQL.

> **Важно:** 
> * Запрещено писать SQL-запросы в контроллерах или обработчиках событий кнопок.
> * Параметры подключения к БД должны быть вынесены в отдельный конфигурационный файл (например, `src/main/resources/database.properties`), а не зашиты в Java-код.

---

## 4. Требования к интерфейсу (UI/UX)
1. **Разметка и стили:**
   * Основные окна приложения должны быть сверстаны с использованием **FXML**.
   * Оформление должно быть вынесено в **CSS-файлы** (кнопки, таблицы, поля ввода, заголовки, индикация ошибок).
   * Интерфейс должен сохранять адаптивность и читаемость при изменении размеров окна.
2. **Табличное представление (`TableView`):**
   * Данные основной сущности выводятся в `TableView` с использованием `ObservableList`.
   * Столбцы должны иметь понятные пользователю заголовки.
   * Технические данные (служебные идентификаторы, хеши и т. п.) пользователю отображаться **не должны**.
   * Таблица должна автоматически обновляться после любых CRUD-операций.
3. **Диалоговые окна и уведомления:**
   * Использование стандартных модальных окон (`Alert`, `Dialog`):
     * Формы добавления и редактирования;
     * Окно **подтверждения удаления** перед выполнением операции (`Alert.AlertType.CONFIRMATION`);
     * Информативные сообщения об ошибках валидации и сбоях работы.
   * **Запрещено** использовать вывод в консоль (`System.out.println`) вместо визуальных уведомлений.

## 5. Функциональные требования

### 5.1. CRUD-операции
* **Просмотр:** отображение списка записей с поддержкой выделения строки.
* **Добавление:** ввод через графическую форму, сохранение в БД и мгновенное отображение в интерфейсе.
* **Редактирование:** открытие формы с автозаполнением текущими данными выбранной записи.
* **Удаление:** удаление выбранной записи только после явного подтверждения пользователем.

### 5.2. Работа со связанными сущностями
* При наличии внешних ключей (FK) ручной ввод ID **запрещен**.
* Выбор связанной записи должен производиться через элементы управления: `ComboBox`, `ListView` или отдельное модальное окно выбора.

### 5.3. Валидация данных
Вся информация проверяется **до отправки запроса в БД**. Проверке подлежат:
* Заполненность обязательных полей;
* Корректность числовых форматов и диапазонов;
* Логическая корректность дат (например, дата окончания позже даты начала);
* Ограничения на длину строк;
* Уникальность значений (если предусмотрено бизнес-логикой);
* Специфические бизнес-ограничения предметной области.
* При ошибке пользователю выводится понятное сообщение с указанием конкретного неверно заполненного поля.

### 5.4. Поиск, фильтрация и сортировка
* **Поиск:** текстовый поиск минимум по нескольким смысловым атрибутам сущности.
* **Фильтрация:** минимум **2 независимых фильтра**, соответствующих специфике предметной области (по статусу, датам, категориям и т. д.).
* **Сортировка:** сортировка данных минимум по **2 параметрам**.

### 5.5. Аналитика и статистика
* Отдельный раздел / окно статистики.
* Расчет и вывод **не менее 5 осмысленных показателей** для предметной области (например: общее количество, распределение по статусам/категориям, среднее/минимальное/максимальное значение числового поля, количество за период, процентная доля).

### 5.6. Экспорт данных
* Экспорт текущей выборки/таблицы в один из форматов: **`.xlsx`** или **`.csv`**.
* Выбор места сохранения файла должен производиться пользователем через **`FileChooser`** (жестко прописывать пути к файлам в коде запрещено).

## 6. Категорические запреты (Антипаттерны)
* ❌ Размещение интерфейса, бизнес-логики и работы с БД в одном классе (God Object).
* ❌ Выполнение SQL-запросов внутри обработчиков событий JavaFX (Event Handlers).
* ❌ Наличие неработающих кнопок, пустых обработчиков или «заглушек».
* ❌ Перехват исключений пустым блоком `catch` или показ технического stack trace пользователю.
* ❌ Хранение паролей и параметров БД непосредственно в коде Java.
* ❌ Абсолютные hardcoded-пути к файлам (например, `C:\Users\ivan\...`).
* ❌ Прием данных из UI без предварительной валидации.

1. **Что предоставляется к защите:**

   * Скрипты инициализации БД PostgreSQL (DDL/DML) и тестовый набор данных.
   * Демонстрация работы приложения "вживую":
     * Запуск системы;
     * Выполнение CRUD-операций и подтверждение удаления;
     * Работа валидации (с демонстрацией отлова некорректных данных);
     * Работа поиска, обоих фильтров и сортировок;
     * Просмотр блока статистики (5 показателей);
     * Экспорт файла через `FileChooser`.
2. **Вопросы на защиту (каждый член команды из 4 человек должен уметь объяснить):**
   * Развертывание базовой инфраструктуры через Docker Compose, проверка healthcheck.
   * Концепции JavaFX: роли `Stage`, `Scene`, `Node`.
   * Жизненный цикл FXML, связь `fx:id` и контроллеров, аннотация `@FXML`.
   * Принцип работы `TableView`, привязка свойств (`PropertyValueFactory` / лямбды), назначение `ObservableList`.
   * Архитектура проекта: разграничение зон ответственности Controller $\to$ Service $\to$ DAO $\to$ JDBC.
   * Реализация валидации, поиска, фильтрации и расчета аналитических метрик.
